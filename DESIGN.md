# Design: serde_markdown

Status: mapping locked (decisions from 2026-09-17 applied)
Crate: `serde_markdown`
License: Apache-2.0

## 1. Goal

A Serde format crate that maps a **root struct** (hand-written or generated by [buffa](https://github.com/anthropics/buffa)) onto a Markdown document:

1. Optional **fields** at the start: a fenced code block, or the same YAML/JSON/TOML **without** a fence (first slice before the first `---`).
2. The rest of the file is **body sections**, split by top-level Markdown dash thematic breaks — except the **last** body field, which is the rest of the document verbatim (§2.7).
3. Which fields are body is **declared**, not inferred from `Vec<u8>`. A body field may have **any** serializable type, including Google well-known types.

Front-matter encoding is delegated to `yaml_serde`, `serde_json`, and `toml`. Protobuf JSON / well-known types come from buffa’s existing `Serialize` / `Deserialize` impls (`buffa` `json` feature, `buffa-types/json`). This crate does not reimplement YAML, JSON, TOML, or proto3 JSON.

```text
from_str(to_string(x)) == x
```

holds when front matter is JSON-shaped (proto3 JSON mapping included) and raw body bytes are valid UTF-8. Body text is verbatim: the crate adds no byte to a section and removes none. Front-matter keys are written in declaration order (§4.1). Byte-exact `to_string(from_str(s)) == s` is still not guaranteed (pretty-print of the fields).

## 2. Document shape

### 2.1 YAML front matter (default on serialize)

````markdown
```yaml
field1: foo
field2: bar
field3: 1
```
Text1 bla bla bla
---
Text2 bal bla bla
````

### 2.2 JSON front matter

````markdown
```json
{
  "field1": "foo",
  "field2": "bar",
  "field3": 1
}
```
Text1 bla bla bla
---
Text2 bal bla bla
````

### 2.3 TOML front matter

````markdown
```toml
field1 = "foo"
field2 = "bar"
field3 = 1
```
Text1 bla bla bla
---
Text2 bal bla bla
````

### 2.4 Bare fields (no fence)

Fields may omit the ` ``` ` wrapper. After the leading prefix (§2.5), the
text up to the first top-level `---` (or EOF if there is none) is YAML, JSON,
or TOML, sniffed like an unlabeled fence (§2.6).

YAML:

```markdown
field1: foo
field2: bar
field3: 1
---
Text1 bla bla bla
---
Text2 bal bla bla
```

JSON:

```markdown
{
  "field1": "foo",
  "field2": "bar",
  "field3": 1
}
---
Text1 bla bla bla
---
Text2 bal bla bla
```

TOML:

```markdown
field1 = "foo"
field2 = "bar"
field3 = 1
---
Text1 bla bla bla
---
Text2 bal bla bla
```

That first slice is fields **only if** it parses as a **mapping** (YAML map,
JSON object, TOML table). A YAML scalar such as `Hello world` is not fields:
the whole remainder is body. A sniffed JSON/TOML document that fails to parse
is an error (the author clearly wrote that syntax).

If the first slice is a mapping and there is no later `---`, the file is
fields-only (body fields follow §4.4).

On serialize, `to_string` still writes a **fenced** ` ```yaml ` block (no
ambiguity with Markdown). Emit this bare shape with `FieldsLayout::Bare`.

### 2.5 Fields are first-only

The structured **fields** block is recognized **only at the start** of the
file (after a discarded prefix).

Skip a leading prefix made of:

- Unicode whitespace (spaces, tabs, newlines, CR);
- top-level dash thematic breaks (`---`, same CommonMark dash-rule as in §2.7).

That prefix is **discarded** only when a fields block follows it. It is not
front matter, not a body section, not a leading empty field. A document that
starts with `---` then YAML then `---` then body is therefore bare YAML fields,
not a leading empty section.

When no fields block is found, nothing is discarded: the body starts at the
first byte of the document. A writer whose body-only document would be read
as fields (its first slice is a mapping) starts it with an explicit empty
fields block instead.

After the prefix, in order:

1. If the next top-level block is a fenced code block (` ``` ` / ` ~~~ `)
   whose info string is `yaml` / `yml` / `json` / `toml` or empty, it is the
   **fenced** fields section. A tagged language selects the parser; empty →
   sniff (§2.6). Any other info string (`rust`, `md`, …) means this fence is
   not fields; fall through to (2) or body.
2. Else take the text until the first top-level `---` (or EOF) as a **bare**
   fields candidate (§2.4). Mapping → fields. Not a mapping → no fields; that
   text is the first body section.
3. A ` ```yaml ` that is not the first block is ordinary Markdown body.

Missing front-matter keys follow ordinary Serde/proto rules (`default`,
`Option`, proto3 implicit presence).

Examples of a valid leading fenced fields block (prefix ignored):

````markdown
---

```yaml
field1: foo
```
body
````

````markdown
```
field1: foo
field2: bar
```
body
````

Not fenced fields — fence is not first, so it is body (the intro may still be
bare YAML fields if it is a mapping before `---`):

````markdown
Intro paragraph

```yaml
field1: foo
```
````

Body-only (first slice is not a mapping):

```markdown
Text1 bla bla bla
---
Text2 bal bla bla
```

### 2.6 Unlabeled fence or bare slice: sniff YAML / JSON / TOML

On **serialize**, fenced output always has an explicit tag (` ```yaml ` by
default). Bare output has no fence and no language tag; format is `Format` plus
`FieldsLayout::Bare`. Round-trip of `to_string` is always fenced and labeled.

On **deserialize**, sniff applies to an unlabeled **first** fence and to a
**bare** first slice. Do not sniff body sections, and do not sniff a fence that
is not first.

Detection (shape, not “try every parser until one succeeds” — YAML would accept almost anything):

1. Trim inner fence text. Empty → YAML, empty mapping.
2. If the first non-space character is `{` or `[` → **JSON**.
3. Else if the first significant line looks like TOML (`key = value`, `[table]`, `[[array]]`, optional `#` comments skipped) → **TOML**.
4. Else → **YAML**.

If the sniffed parser then fails: **fenced** unlabeled block → that parse error
(do not fall back). **Bare** first slice: JSON/TOML parse failure → error;
YAML that is not a mapping (scalar, sequence) → not fields, treat as body
(§2.4). Do not fall back from JSON to YAML.

````markdown
```
field1: foo
field3: 1
```
````

→ YAML.

The same text without the fence, followed by `---`, is also YAML fields.

````markdown
```
{
  "field1": "foo",
  "field3": 1
}
```
````

→ JSON.

````markdown
```
field1 = "foo"
field3 = 1
```
````

→ TOML.

### 2.7 How the file is split

Do **not** split on raw lines. Parse the document with a CommonMark parser and use the AST / event stream.

Recommended parser: **`pulldown-cmark`** (CommonMark; the parser rustdoc and Cargo use). Source offsets come from `OffsetIter`.

Algorithm:

1. Parse the full document with source offsets (`OffsetIter`).
2. Track block nesting (blockquote, list, item, table, footnote).
3. From the start, skip whitespace and top-level dash `---` rules (§2.5).
4. **Fenced fields:** if the next top-level block is a fenced code block whose
   info string (trimmed, case-insensitive, first token) is `yaml` / `yml` /
   `json` / `toml` or empty, it is the fields fence. Tagged language selects
   the decoder; empty → sniff (§2.6). Any other info string (`rust`, `md`, …)
   is not a fields fence.
5. **Bare fields:** if there is no fields fence, the text until the next
   top-level dash `---` (or EOF) is a fields candidate. Sniff (§2.6). Mapping
   → fields; otherwise that text starts the body (§2.4).
6. **Body:** everything after a recognized fields block. Split on remaining
   top-level dash `---` rules. That is `Event::Rule` whose source is a dash
   thematic break (0–3 spaces indent, three or more `-`, optional spaces
   between markers), **and** a top-level setext H2 underline of dashes: a
   paragraph followed immediately by `---` is a CommonMark setext heading,
   not `Event::Rule`. ATX headings (`## …`) and `===` setext H1 underlines
   are not separators. Breaks inside fences, lists, quotes, or tables are
   ordinary content. Leading `---` skipped in step 3 are not body separators.
   Only the first `n − 1` such rules split, where `n` is the number of body
   fields; the **last body field is every byte after its separator**, never
   parsed and never trimmed, so it may hold `---` lines, setext underlines,
   tables, fences, and anything else. A reader removes exactly the separator:
   the line break that ends the earlier section, the `---` line, and its line
   break. A single body field directly after a fenced block (or in a document
   with no fields) takes the region as is; when its value is empty or itself
   starts with a `---` line, the writer puts one `---` line before it and the
   reader drops that line.
7. `***` and `___` thematic breaks are **not** section separators. They stay
   inside a section so authors can still draw a visual `<hr>` without starting
   a new field.

On serialize, always emit the canonical separator `\n---\n` between body
sections (and between bare fields and the first body section). A body value
that is not the last and holds a top-level `---` line, an unclosed fence, or
ends with a carriage return would split differently on read, so it is
`ErrorKind::Body` at write time. Never emit `***` / `___` as a field boundary.
Never emit a leading `---` prefix except before an empty or `---`-led single
body field (step 6). Fenced
serialize never uses an unlabeled fence; bare serialize never wraps fields in
` ``` `.

Why only dashes: the original format uses `---`. A Markdown-aware parser is
required so a `---` inside a body code fence does not split fields. Treating
every CommonMark `<hr>` as a split would make `***` in prose change the struct
layout.

## 3. Marking body fields

Classification is explicit and only at the **root** message/struct. Nested fields, including nested `Vec<u8>` or nested WKT, stay in front matter (or inside a structured body value).

### 3.1 Hand-written Rust: derive + field attribute

```rust
use serde::{Deserialize, Serialize};
use serde_markdown::Markdown;

#[derive(Debug, PartialEq, Serialize, Deserialize, Markdown)]
struct Page {
    field1: String,
    field2: String,
    field3: i32,
    #[markdown(body)]
    text1: String,
    #[markdown(body)]
    text2: String,
}
```

`#[markdown(body)]` is our attribute, consumed by `#[derive(Markdown)]`. It is **not** Serde’s `#[serde(tag = "...")]` (that is internally tagged enums). Serde attributes on the same field still apply (`rename`, `default`, `skip_serializing_if`, …). Body membership uses the **Serde field name** (after `rename`).

The derive emits:

```rust
impl serde_markdown::Markdown for Page {
    const BODY_FIELDS: &'static [&'static str] = &["text1", "text2"];
}
```

`to_string` / `from_str` require `T: Serialize + Markdown` / `T: Deserialize + Markdown`. Types with no body fields still implement `Markdown` with an empty list (fields-only documents).

Without the derive, implement `Markdown` on the type (empty `BODY_FIELDS` for fields-only). `to_string_with` selects fence language and layout; it does not take a body-field list.

### 3.2 Protobuf (buffa): field option + editions feature

Ship `markdown/options.proto` (protobuf package `markdown`) inside the crate, at `rust/markdown/proto/markdown/options.proto`, and read it from codegen. The Rust crate name stays `serde_markdown`.

Works for **proto3**, **Edition 2023**, and **Edition 2024**. Proto2 is out of scope unless it falls out of buffa for free.

#### Field option (primary, all syntaxes)

```protobuf
syntax = "proto3";
package example;

import "google/protobuf/timestamp.proto";
import "markdown/options.proto";

message Page {
  string field1 = 1;
  string field2 = 2;
  int32 field3 = 3;
  string text1 = 4 [(markdown.body) = true];
  google.protobuf.Timestamp published = 5; // front matter
  // proto3 `optional` = explicit presence (protoc ≥ 3.15). Without it,
  // proto3 scalars have implicit presence (unset == default).
  optional string appendix = 6 [(markdown.body) = true];
}
```

#### Editions (2023 / 2024)

The same field option works on edition files. A FeatureSet feature cannot be named `markdown.body`: that identifier is already the FieldOptions extension in package `markdown`, and FeatureSet custom numbers also have to be reserved with the protobuf project.

```protobuf
edition = "2024";
package example;

import "markdown/options.proto";

message Page {
  string field1 = 1;
  string text1 = 2 [(markdown.body) = true];
}
```

Shipped options file (`rust/markdown/proto/markdown/options.proto`; field number `20260917`).
The file is **proto3** so proto3 toolchains without editions can compile it;
Edition 2023 / 2024 files import it the same way.

The file sits inside the crate, so the Cargo dependency is the one channel a
consumer needs: a build script passes `serde_markdown::PROTO_INCLUDE` as an
include path, and Bazel reaches the file in the crate's crate_universe
repository through an annotation (§6.5). There is no Bazel module to depend
on as well, so the proto and the crate cannot drift to different versions.

```protobuf
syntax = "proto3";
package markdown;

import "google/protobuf/descriptor.proto";

extend google.protobuf.FieldOptions {
  bool body = 20260917;
}
```

#### Buffa integration

Buffa already emits proto3-JSON `Serialize` / `Deserialize` when `generate_json(true)` / `json=true`. Those impls must stay intact so `serde_json::to_string(&msg)` remains canonical proto JSON.

serde_markdown does **not** change that mapping. Extra generated pieces:

1. `#[derive(serde_markdown::Markdown)]` on the owned message (via `message_attribute`).
2. `#[markdown(body)]` on marked fields (via `field_attribute`).
3. `BODY_FIELDS` lists serde JSON names (see below).

When buffa serializes a message, proto3 JSON names the keys, not the `.proto` identifiers. `string published_at = 1` is Rust field `published_at` with `#[serde(rename = "publishedAt")]`, so the YAML fence key is `publishedAt`. `BODY_FIELDS` must contain `"publishedAt"`. One-word names (`field1`, `text1`) are unchanged.

Helper:

```rust
// build.rs
// `buffa_build::Config` has no `apply` hook that receives the compiled
// FileDescriptorSet, so the helper walks a set the caller already has
// (from `buf build --as-file-descriptor-set` or `protoc --descriptor_set_out`)
// and returns `message_attribute` / `field_attribute` pairs.
let fds = /* FileDescriptorSet */;
let attrs = serde_markdown::buffa::annotate_markdown_body(&fds);
let mut config = buffa_build::Config::new()
    .files(&["proto/page.proto"])
    .includes(&[
        "proto/",
        serde_markdown::PROTO_INCLUDE,
        // directory that contains `google/protobuf/descriptor.proto`
    ])
    .generate_json(true);
for (path, attr) in attrs.message_attributes() {
    config = config.message_attribute(path, attr);
}
for (path, attr) in attrs.field_attributes() {
    config = config.field_attribute(path, attr);
}
config.compile()?;
```

`annotate_markdown_body` walks the `FileDescriptorSet`, finds fields with `(markdown.body) = true`, and returns the attributes. The caller injects them with buffa `message_attribute` / `field_attribute`. No fork of `buffa-codegen`. The helper is public. Feature `buffa` is off-default; Bazel still enables it for CI.

v1 targets **owned** generated messages. `PageView<'a>` is a non-goal until owned round-trips are solid (views already `Serialize` with `json`, so a later pass can allow `to_string` on views).

## 4. Type mapping

### 4.1 Front matter

Every root field not listed in `BODY_FIELDS`. Encoding is the fence language applied to the value produced by `T`’s `Serialize` (for buffa: proto3 JSON data model written as YAML/JSON/TOML). Keys are written in the order `Serialize` emits them: declaration order for a derived struct, field order for a buffa message — in every fence language and layout. On read, keys may come in any order.

Unknown fence keys and missing front-matter fields: Serde / buffa defaults (`deny_unknown_fields`, `#[serde(default)]`, proto3 implicit presence, `MessageField<T>`, `Option<T>`). The Markdown layer does not add a second policy.

### 4.2 Body

One logical section per `BODY_FIELDS` entry, in **declaration order** of those fields (not alphabetical, not proto number). The field **name does not appear** in the Markdown.

The field type is unrestricted (`String`, `i32`, nested message, `Option<T>`, `buffa::MessageField<T>`, any WKT, …).

How a section is encoded depends on what that type’s `Serialize` produces (see §6.3). Typical cases:

| Type | Section text |
| --- | --- |
| `String`, `&str`, proto `string`, `StringValue` | raw Markdown (verbatim) |
| Rust `Vec<u8>` / `&[u8]` | raw UTF-8 Markdown (error if invalid UTF-8 on serialize) |
| proto `bytes` / `BytesValue` | proto3 JSON: **base64 text**. Prefer `string` for human Markdown |
| scalars (`bool`, numbers) | YAML/JSON/TOML scalar in the fence’s language |
| nested struct / proto message | YAML/JSON/TOML object |
| `Option<T>` / unset `MessageField<T>` | see §4.4 |
| WKT | proto3 JSON form of that WKT, then the same raw-vs-structured rule |

### 4.3 Google well-known types

Support is **both** in the fence and in body sections. Implementation: depend on `buffa-types` with `json` (and generated messages with `generate_json`). Do not hand-roll RFC 3339.

| WKT | Proto3 JSON (serde) | In front matter (YAML example) | As a body section |
| --- | --- | --- | --- |
| `Timestamp` | RFC 3339 string | `published: "2026-09-17T02:42:00Z"` | `2026-09-17T02:42:00Z` |
| `Duration` | string, e.g. `"1.5s"` | `ttl: "1.5s"` | `1.5s` |
| `FieldMask` | comma-separated paths | `mask: "a,b.c"` | `a,b.c` |
| `Empty` | `{}` | `meta: {}` | `{}` |
| `Struct` / `Value` / `ListValue` | native JSON object / value / array | YAML/JSON/TOML of that value | same, as the section |
| `Any` | `{"@type": "...", ...}` | mapping with `@type` | mapping as the section |
| wrappers (`Int32Value`, …) | unwrapped JSON scalar | scalar | scalar / raw string for `StringValue` |
| `NullValue` | `null` | `null` | empty or `null` |

`Any` packing requires a `TypeRegistry` (`buffa_types::register_wkt_types`). Document that callers who use `Any` must install the registry the same way they do for `serde_json`.

Hand-written Rust structs may use `buffa_types::Timestamp` (etc.) as field types; they get the same mapping.

### 4.4 `Option` and proto presence

Supported from v1, including proto `optional`, edition explicit presence, and `buffa::MessageField<T>`.

Body sections are **positional**. Unset values in the **middle** of the body list still occupy a slot so later fields do not shift.

#### Serialize

1. Encode each body field to a section, or to “absent”.
2. Absent means JSON `null` / missing key / `None` / unset `MessageField`.
3. Drop **trailing** absent sections (the file does not end with a stack of `---`).
4. Keep absent sections that have a later present body field; write them as **empty** sections (two `---` in a row, or a leading `---` if the first body field is absent).

#### Deserialize

1. Assign sections to body fields in order.
2. If sections run out, remaining fields must all be optional → `None` / unset; otherwise `missing section`.
3. There are no extra sections: once the separators of the first `n − 1`
   fields are seen, the rest of the document is the last field, `---` lines
   included.
4. Empty section:
   - optional field → `None` / unset
   - required `String` / bytes → empty value
   - required structured type → error (empty is not `{}`)
5. Last body field: its presence is its separator. No separator → `None` /
   unset; a separator followed by nothing → `Some("")`; anything after the
   separator, `""` included, is the literal text.
6. A body field that is not the last: an optional raw string `Some("")` is
   written as a section whose content is the two characters `""` (JSON/YAML
   empty string). That is distinct from `None` (empty section). An optional
   middle value that is literally `""` cannot be written (`ErrorKind::Body`).

```text
Some("a"), None, Some("c")     →  a\n---\n\n---\nc
Some("a"), None, None          →  a
None, Some("a")                →  ---\na
Some("a"), Some("")            →  a\n---\n""
```

The `""` convention applies only to optional body fields that are not the last; the last field carries any text, `""` included.

### 4.5 Count mismatch (non-optional)

| Situation | Result |
| --- | --- |
| Same number of present body values and sections | OK |
| `---` lines after the last field's separator | Part of the last field |
| Missing section for a required body field | Error |
| Zero body fields | Fence only (or empty file if no front matter either) |
| All fields are body, all present | Body-only file, no fence |

## 5. Public API

```rust
pub fn to_string<T: Serialize + Markdown>(value: &T) -> Result<String, Error>;
pub fn to_vec<T: Serialize + Markdown>(value: &T) -> Result<Vec<u8>, Error>;
pub fn to_writer<W: io::Write, T: Serialize + Markdown>(
    writer: W,
    value: &T,
) -> Result<(), Error>;

pub fn from_str<T: DeserializeOwned + Markdown>(s: &str) -> Result<T, Error>;
pub fn from_slice<T: DeserializeOwned + Markdown>(bytes: &[u8]) -> Result<T, Error>;
pub fn from_reader<R, T>(reader: R) -> Result<T, Error>
where
    R: io::Read,
    T: DeserializeOwned + Markdown;
```

Fence language on **serialize**:

```rust
#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
pub enum Format {
    #[default]
    Yaml,
    Json,
    Toml,
}

pub fn to_string_with_format<T: Serialize + Markdown>(
    value: &T,
    format: Format,
) -> Result<String, Error>;

#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
pub enum FieldsLayout {
    #[default]
    Fenced,
    Bare,
}

pub fn to_string_with<T: Serialize + Markdown>(
    value: &T,
    format: Format,
    layout: FieldsLayout,
) -> Result<String, Error>;
```

- `to_string` → `Format::Yaml` + `FieldsLayout::Fenced` (` ```yaml `).
- JSON / TOML only when the caller passes `Format::Json` / `Format::Toml`.
- `FieldsLayout::Bare` writes the example in §2.4 (no fence; `---` before the first body section).
- **Deserialize:** explicit fence tag wins. Unlabeled first fence and a **bare** first slice are sniffed (§2.6). A first slice that is not a mapping is body, not fields. Structured body sections use the fields format when fields were present, otherwise YAML. A JSON/TOML code block that is not first is Markdown body, not a format switch.

```rust
pub trait Markdown {
    /// Serde field names of body sections, declaration order.
    const BODY_FIELDS: &'static [&'static str];
}

pub const DESIGN: &str = "DESIGN.md";
pub const PROTO_INCLUDE: &str = /* CARGO_MANIFEST_DIR/proto */;
```

`from_str` / `from_slice` / `from_reader` require `DeserializeOwned` because the mapping layer owns a JSON IR; they do not borrow from the input. Feature `buffa` exports `serde_markdown::buffa::annotate_markdown_body`.

### Async form (feature `tokio`)

Feature `tokio` (off by default) adds the module `serde_markdown::tokio`: the async twin of every function above, under the same name, writing and reading the same document with the same failures. `to_writer` and `from_reader` take tokio's `AsyncWrite` / `AsyncRead` and await the I/O; `to_writer` does not flush, like its twin.

```rust
pub async fn to_string<T: Serialize + Markdown>(value: &T) -> Result<String, Error>;
pub async fn from_str<T: DeserializeOwned + Markdown>(s: &str) -> Result<T, Error>;
pub async fn to_writer<W, T>(writer: W, value: &T) -> Result<(), Error>
where
    W: tokio::io::AsyncWrite + Unpin,
    T: Serialize + Markdown;
// … and to_string_with_format, to_string_with, to_vec, from_slice, from_reader
```

The async form is native, not the sync form on another thread. Writing and reading are each one algorithm cut into steps (`src/drive.rs`): the sync functions run the steps to the end; the async functions run the same steps and call `tokio::task::consume_budget` between them, which yields to the scheduler only when the task's cooperative budget is spent. No thread is spawned and nothing runs on the blocking pool, so a caller awaits these functions as they are.

- Writing: serialize the value's body fields; encode the fields block; check each body section (one step per section); assemble the document.
- Reading: split the document; decode the fields block; deserialize the value.

A value's own `Serialize` or `Deserialize`, a YAML / JSON / TOML codec call, and the `pulldown-cmark` pass over a document are one step each; a structured body section is decoded inside the deserialize step. A future borrows the value it writes, so it is `Send` when the value is `Sync`.


Feature `buffa` is **off-default**. Bazel CI still enables it. `annotate_markdown_body` is public (not `doc(hidden)`).

YAML crate: **`yaml_serde` 0.10** (YAML Organization fork of `serde_yaml`). Not `serde_yaml` (archived), not `serde_yml` (unmaintained / RUSTSEC).

`from_str` of a ` ```json ` document without the `json` feature → `ErrorKind::FormatDisabled` (`Display` is `format not enabled: json`). Same for yaml/toml.

IR: **`serde_json::Value`** is always linked (fields IR), so feature `json` is empty (`json = []`) and only gates JSON fence dump/load. Preferred v1: `json` stays in the default feature set because buffa WKT and proto JSON are JSON-shaped.

## 6. Architecture

```text
Markdown text
    │
    ▼
parse.rs     pulldown-cmark → (Option<Fence>, Vec<Section>)
    │
    ▼
de.rs        fence → yaml_serde / serde_json / toml → IR map
             body field F_i ← section deserializer (raw or format)
             other fields ← IR
             T::deserialize

T: Serialize + Markdown
    │
    ▼
ser.rs       serde_json::to_value(T)   (uses T’s Serialize: proto JSON if buffa)
             pull BODY_FIELDS out, render sections
             remaining map → yaml_serde / serde_json / toml
             if remaining empty → omit fence
             join sections with ---
```

### 6.1 Root type

Root must be a named struct (`serialize_struct`). Maps, sequences, tuple structs, and enums as the document root are errors. Nested values inside front matter or inside a structured section are unrestricted.

### 6.2 Why a `Markdown` trait instead of `serialize_with`

`#[serde(with = "...")]` would wrap body fields for **every** format, including buffa proto JSON. The trait keeps `Serialize`/`Deserialize` untouched: `serde_json::to_string(&page)` stays proto JSON; `serde_markdown::to_string(&page)` is the Markdown view of the same impl.

### 6.3 Rendering a body section

After `serde_json::to_value` of the whole root (or a per-field serialize):

| JSON value of that field | Written section |
| --- | --- |
| missing / `Null` | absent (see §4.4) |
| `String s` | raw `s` (no extra quotes) |
| `Number` / `Bool` | fence-format scalar (`true`, `1`) |
| `Object` / `Array` | fence-format dump (`yaml_serde::to_string`, pretty JSON, pretty TOML) |
| Rust body `Vec<u8>` | UTF-8 raw, **before** JSON (otherwise it would become `[84, 101, …]`) |

Detecting `Vec<u8>`: while capturing the root struct, if the field is in `BODY_FIELDS` and the value calls `serialize_bytes` / `serialize_byte_buf`, or is a seq of only `u8`, treat as raw UTF-8. Buffa `bytes` fields serialize as a **string** (base64) under proto JSON; they follow the `String` row unless we add a later opt-in.

Deserializing a section:

- `deserialize_option`: empty → `None`; else `Some` with the rest of this list.
- `deserialize_string` / `str` / `bytes` / `byte_buf`: raw section (bytes: UTF-8).
- `deserialize_i64` / `bool` / …: parse as fence-format scalar (body-only → YAML).
- `deserialize_struct` / `map` / `seq` / `any`: parse the section as YAML/JSON/TOML, then deserialize.

That last path is what makes **arbitrary types** and **WKT objects** work without a type switch in this crate.

## 7. Errors

One handwritten crate type `Error` in `src/error.rs`, in the same shape as
`serde_json::Error`: a small public `ErrorKind`, human `Display`,
`std::error::Error`, and `serde::{ser,de}::Error`. Callers **match on
`kind()`**. They must not parse `Display`.

Do **not** use `thiserror`, `anyhow`, or a protobuf error envelope (`code` /
`path` / `repeat` / `stack`). Those fit a vault/agent API, not a Serde
format. `serde::{ser,de}::Error` (`custom`, `missing_field`, …) is
implemented by hand on this `Error`.

Public surface (names locked):

```rust
pub enum ErrorKind {
    Syntax,
    FrontMatter,
    Body,
    Type,
    FormatDisabled,
    Io,
}

impl Error {
    pub fn kind(&self) -> ErrorKind { /* … */ }
    /// Byte offset into the input. `Some` only for `Syntax`.
    pub fn offset(&self) -> Option<usize> { /* … */ }
}
```

`std::error::Error::source()` is set for wrapped decoder and IO failures
(`FrontMatter`, `Io`, and structured-body decoder failures under `Body`).
It is unset for `Syntax`, `Type`, and `FormatDisabled`.

| Kind | When |
| --- | --- |
| `Syntax` | Unclosed fence, bad info string, CommonMark/fence scan failure, invalid UTF-8 on `from_slice`. Carries a byte offset. |
| `FrontMatter` | Wrapped `yaml_serde` / `serde_json` / `toml` error while decoding the fields slice (“in fence” / bare fields). `source()` is the decoder error. |
| `Body` | Section count, empty required structured section, invalid UTF-8 on `Vec<u8>` serialize, or a wrapped decoder error on a structured body section (`source()` set). |
| `Type` | Root is not a named struct; Serde mapping-layer `custom` / `missing_field` for this format (not the YAML/JSON/TOML decoder). |
| `FormatDisabled` | Fence language not in compiled features |
| `Io` | `to_writer` / `from_reader`. `source()` is `std::io::Error`. |

Exact `Display` wording lives in rustdoc. `FormatDisabled` displays as `format not enabled: yaml` (or `json` / `toml`).

## 8. Whitespace and encoding

- Documents are UTF-8. `from_slice` fails on invalid UTF-8.
- Do not trim sections. Preserve every byte of a section: inner blank lines, trailing spaces, leading and trailing line breaks.
- Serialize: no leading blank line; one newline after the closing fence; separator `\n---\n`; no trailing `---` after the last emitted section; the document ends with the last byte of the last section — no newline is added at EOF.
- Front-matter pretty-print: YAML = `yaml_serde` default; JSON = serde_json pretty, 2 spaces; TOML = `toml::to_string_pretty`.

## 10. Non-goals (v1)

- Pandoc / Jekyll `---` YAML `---` front matter as an alternate syntax.
- Splitting body by ATX headings (`## Intro`) instead of `---`.
- Streaming huge files.
- Preserving YAML comments, anchors, or key style.
- `no_std`.
- Generated `Markdown` impl for buffa **views**.
- Forking `buffa-codegen`.
- Treating proto `bytes` body fields as raw UTF-8 (they stay proto JSON base64 unless we add an opt-in later).
- `thiserror` / `anyhow` for the crate `Error`.
- A protobuf error envelope (`code`, `path`, `repeat`, `stack`).
